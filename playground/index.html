Use the library

@irail/planner is an ESM npm library for Node.js 22.12+ and modern browsers. It scans Arrow connection pages locally and returns alternatives with departure time, arrival time and vehicle changes.

Not yet published on npm. This is a work in progress: npm install @irail/planner will not work until the first release. For now, clone the repository and install from the checkout: 

git clone https://github.com/iRail/planner
cd planner && npm ci
npm install /path/to/planner   # from your own project

Start the playground locally with npm run dev. This Node.js example reads the live iRail CDN timetable; pick stops by name instead of fixed indices: 

import { createPlanner } from '@irail/planner';

const planner = createPlanner({
  dataUrl: 'https://irail.github.io/iRail-cdn/manifest.jsonld',
});
const [source] = await planner.init();
const stop = (iri) => source.stops.id.indexOf(iri);
const result = await planner.plan({
  // Gent-Sint-Pieters to Liège-Guillemins
  origin: { sourceId: source.id, stopIdx: stop('https://irail.be/id/be.sncb/stops/S8892007') },
  destination: { sourceId: source.id, stopIdx: stop('https://irail.be/id/be.sncb/stops/S8841004') },
  departureAfter: Math.floor(Date.now() / 1000),
  maxWalkMeters: 1000,
});
console.log(result.options);

Stop indices refer to the loaded source. source.stops.id contains the publisher's stop IRIs; find an index with source.stops.id.indexOf(stopIri), or use { lon, lat } as either endpoint.

Keep the browser responsive

With a worker-aware bundler such as Vite, import the browser entry. The playground uses this same API: 

import { PlannerClient, createPlannerWorker } from '@irail/planner/browser';

const client = new PlannerClient(createPlannerWorker());
const sources = await client.request('init', { dataUrl: manifestUrl });
const result = await client.request('plan', query, onProgress);
client.close();

API reference

Method Behavior
createPlanner(options) Returns a planner. Options: dataUrl, optional fetch, and cacheBytes (64 MiB default).
await planner.init(url?) Loads reference tables and returns source metadata, stop IRIs, names and coordinates. Call again to load a new release.
await planner.plan(query, onProgress?) Returns found, options, totalOptions, window, scanned and diagnostics. Each option has departure, arrival, transfers and ride/walk legs.
await planner.isochrone(query, onProgress?) Uses a coordinate origin and maxDurationSeconds (60–10800). Returns reachable stop points and travel durations.

Journey queries require origin, destination, and departureAfter as UTC epoch seconds. Optional sourceIds limits active feeds. maxWalkMeters is 0–5000 (Node API default: 1000), for each continuous walk at 5 km/h.

windowMode: 'adaptive' is the default: find the earliest arrival in 24 hours, then search a window twice that elapsed time, capped at 24 hours. Use 'full' to search the whole day. Results contain up to six nondominated alternatives; later or slower departures outside the adaptive window may be excluded.

Ride legs expose the publisher's tripIri, routeIri, connectionIri (boarding connection), boardStopIri, and alightStopIri. Times are always seconds, not JavaScript milliseconds. Calls on a planner instance run sequentially and reuse its connection cache.

Bring your timetable

Use an absolute HTTP(S) manifest URL (any filename), or a directory URL ending in / containing manifest.jsonld. For multiple feeds, a directory can contain sources.json: 

{
  "sources": [
    { "id": "nmbs", "name": "NMBS / SNCB", "manifest": "nmbs/manifest.jsonld" }
  ]
}

The loader supports LC schemaVersion: '2-alpha', Arrow IPC files, IRI identifiers, regional page lists, scheduled pagination and redirect pagination. Relative links resolve against response URLs. Tables and pages must share the manifest's release ID. Cross-origin publishers must enable CORS.

Routing uses scheduled data. GTFS Realtime updates, linked-trip transfers (types 4/5), and shapes are not implemented. Linked-trip transfers are rejected explicitly; transfer overrides between different stations are ignored. Walking uses straight-line distance and does not model streets, accessibility or barriers.

Read the LC 2.0-alpha draft for the manifest and table schemas, and the README for development, test provenance and GitHub Pages setup.
